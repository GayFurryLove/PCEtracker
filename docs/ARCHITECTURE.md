# Архитектура

Принцип: модули независимы, зависимости идут только вниз. Звук и движок трекера не
знают про интерфейс и тестируются без окна. Абстракций ровно столько, сколько нужно.

```
              ui (SDL2)                          этап 3-4
                 │
   project_io ── tracker ── instruments/modulation    этапы 2, 4, 5
                 │
        ┌────────┼──────────┬──────────┐
     renderer   wav_export  hes_export rom_export      этапы 2, 6, 7
        │
       psg  (HuC6280 PSG)                              этап 1  ✔
```

## Ключевое правило: трекер = драйвер

Плеер в трекере выдаёт **только записи в регистры PSG** раз в тик (60 Гц кадр) плюс
DDA по таймеру — ровно то, что будет делать драйвер на 6280. Он не трогает звук
после чипа. Поэтому:

- всё, что слышно в трекере, физически исполнимо на консоли;
- на этапе 6 тест прогоняет экспортированный HES на эмуляторе CPU 6280 и сравнивает
  поток записей в регистры с плеером трекера кадр за кадром.

## Модуль 1: `pce::Psg` (`src/psg/psg.h`)

Единственный вход в звук. Ничего не знает о песнях.

| Вызов | Что делает |
|---|---|
| `Psg(revision, sampleRate)` | `PSG_REV_HUC6280` или `PSG_REV_HUC6280A`; любая частота 8–192 кГц |
| `write(reg, value)` | запись регистра `$080x` в текущий момент времени |
| `writeChannel(ch, reg, value)` | выбор канала + запись (как делает CPU) |
| `advance(clocks)` | эмуляция N тактов PSG (7.159 МГц) |
| `render(out, frames)` | эмулировать сколько нужно и выдать N стерео-кадров |
| `read(out, max)` / `available()` | забрать уже готовые кадры |
| `channelPeriod/Control/peekWave` | состояние для индикаторов UI и тестов |

Время: 1 кадр NTSC = 119210 тактов PSG, тик таймера = 1024 такта (~6991 Гц).

Внутри: `huc6280_psg_core.*` — ядро Mednafen без изменений логики, blip_buf —
band-limited ресемплинг и простой high-pass, убирающий постоянную составляющую
(точная АЧХ выходного тракта консоли пока не моделируется).
Память фиксирована (буфер на 1 с резервируется в конструкторе), потоков нет.
